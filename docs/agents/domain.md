# Domain Docs

本仓库的领域文档如何被工程技能消费。

## 探索之前先读这些

- **`GLOSSARY.md`**（仓库根目录）：本项目的规范术语。写 issue 标题、重构提案、假设、测试名时，一律使用这里定义的词，不要漂移到 `_Avoid_` 列出的同义词。
- **`docs/adr/`**：读与你即将改动的区域相关的 ADR。

若这些文件不存在，**静默继续**——不要提示缺失，也不要建议预先创建。术语或决策真正落定时，由 `/domain-modeling` 惰性创建。

## 文件结构

本仓库是**单上下文**：

```
/
├── GLOSSARY.md
├── docs/
│   ├── adr/
│   │   ├── 0001-兼容止于语义层.md
│   │   ├── 0002-单进程本地服务.md
│   │   └── 0003-预设排布生效.md
│   ├── research/          ← 外部格式调研
│   └── specs/             ← 规格
└── src/
```

出现 `GLOSSARY-MAP.md` 时才表示多上下文；本仓库没有。

## 术语不在表里怎么办

那是一个信号：要么你在发明项目并不使用的语言（该重新考虑），要么确实有缺口（记下来，交给 `/domain-modeling`）。

## 与 ADR 冲突时

如果你的输出与既有 ADR 矛盾，**显式指出**，不要静默认覆盖：

> _与 ADR-0007（事件溯源订单）冲突，但值得重开，因为……_
