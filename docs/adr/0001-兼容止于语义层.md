# 酒馆兼容止于语义层：不追运行时

**Status**: accepted；其中 prompt 排布一项已被 [ADR 0003](0003-预设排布生效.md) 取代

酒馆（SillyTavern）的价值一半在数据格式（角色卡、世界书、预设），一半在运行时（prompt 装配、世界书递归扫描、宏引擎、regex、STscript）。格式解析是机械工作；完整的运行时复刻是数周量级的语义工程。

本项目决定：**解析全部格式，并还原影响玩家可感知体验的那部分运行时语义**——角色字段注入、世界书按关键词激活与位置注入、核心替换宏。**不实现**：世界书递归扫描、`probability`、分组评分、定时效果、regex 扩展、STscript。

## 考虑过的替代方案

- **完整复刻运行时**：100% 保真，但把 MVP 变成季度项目，且永远追不上上游变更。
- **只做素材层（L1）**：一天就能做完，但导进来后角色性格与设定明显走样，"可导入酒馆资料"这个卖点不成立。

## 后果

- 依赖 regex 修正、STscript 自动化的卡，行为会与酒馆不同；界面必须显式告知，而不是让玩家自己困惑。
- 世界书里的 `probability`、`group`、递归开关会被读取但不生效——必须出现在导入报告里，不能静默丢弃。
- 边界划在这里：将来想支持某个机制时，先扩激活引擎，不扩脚本运行时。
