# 预设的 prompt 排布真正生效

**Status**: accepted

[ADR 0001](0001-兼容止于语义层.md) 原本决定不复刻酒馆的 `prompt_order`。后来"素材可编辑"这一需求推翻了它：用户会带着自己反复调过的预设过来，若排布无效，预设就降级成"一堆采样参数"，导入预设这件事失去大部分意义。

决定实现一个真正的装配器：读 `prompt_order` → 按 `enabled` 逐个展开内置 identifier → 处理 marker 占位 → 自定义项原样注入。

在排布走完之后，**固定追加一段"导演模式补丁"，不可关闭**。原因不是保守，是语义：酒馆的每一份预设都建立在"模型扮演单个角色、对 `{{user}}` 说话"这个假设上，而导演模式里没有 `{{user}}`，模型要演所有角色。不覆盖这层假设，最好的结果也只是拿到一份单人 RP 的产出。

## 考虑过的替代方案

- **只用采样参数**：成本最低，但等于告诉用户"你的预设只值几个数字"。
- **复刻排布但不加补丁**：技术上更"纯"，实际会产出格式错乱的单人对话，且拿不到岔路与状态。

## 后果

- 装配器从模板拼接变成解释器，工作量约为原方案的三倍。
- 多角色使角色相关槽位（`charDescription`、`charPersonality`、`scenario`）没有酒馆先例：本项目的定义是**按演员表逐个展开**，每个在场角色占一段。
- 不在场角色不进入角色槽位，只在"在场名单"里保留一行摘要——否则上下文会被十张卡撑爆。
- 必须提供**装配预览**（显示最终发出的完整 prompt）。排布可解释、可改的前提下，不给人看装配结果等于让人瞎调。
