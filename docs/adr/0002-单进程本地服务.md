# 单进程本地服务：Node + SQLite + React，无多租户

**Status**: accepted

目标用户是自己开一个窗口玩的人。决定采用**单个本地 Node 进程**同时提供 API 与静态前端，数据落本地 SQLite，模型密钥存本地配置。不引入账号体系、多租户、外部数据库或桌面壳。

## 考虑过的替代方案

- **纯浏览器 SPA + IndexedDB**：零安装，但 OpenAI 兼容端点的 CORS 普遍不放行，密钥也只能裸存浏览器——这两条否掉了它。
- **桌面壳（Tauri / Electron）**：打包与签名成本高，而酒馆生态本身是 Web 形态，增值不匹配成本。
- **可部署的多人 Web 服务**：需要认证、租户隔离、密钥托管，成本翻倍，且与"自己玩"的初衷相悖。

## 后果

- 数据与密钥只在本机；跨设备同步要用户自己搬 SQLite 文件。
- 代码不写死单用户假设（对局与消息都带归属），将来加多用户不必重构数据模型。
- 选内置 `node:sqlite` 而非 `better-sqlite3`，避免 Windows 上的原生编译依赖。
